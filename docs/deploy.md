# Deploying Banahaw Reservations

The live setup has three parts, all in or near Singapore:

| Part | Service | What it runs |
| --- | --- | --- |
| Database | [Neon](https://neon.tech), AWS Singapore | PostgreSQL 16 |
| API | [Render](https://render.com), Singapore | `backend/` Docker image, from `render.yaml` |
| Web app | [Cloudflare Pages](https://pages.cloudflare.com) | `frontend/` built with Vite |

A nightly GitHub Action (`.github/workflows/backup.yml`) backs up the database and
checks that the backup restores.

Do the steps in order. It takes about 15 minutes. Each one ends with a value you
paste into the next step.

## 1. Neon: the database

1. Sign up at neon.tech, then **Create project**.
   - Name: `banahaw`
   - Postgres version: **16** (the version the tests run on)
   - Region: **AWS Asia Pacific (Singapore)**
2. On the project dashboard, click **Connect**. Turn **Connection pooling off**,
   then copy the connection string. It looks like
   `postgresql://neondb_owner:...@ep-....ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.

   Keep it private. Anyone with this string can read every booking.

**You now have:** the database URL.

## 2. Render: the API

1. Sign up at render.com with your GitHub account and allow access to `meroclemente12/sms`.
2. **New > Blueprint**, pick the `sms` repository, branch `main`. Render reads `render.yaml`
   and shows one service, `banahaw-api` (Singapore, Starter plan).
3. It asks for two values:
   - `DATABASE_URL`: the Neon connection string from step 1.
   - `CORS_ORIGINS`: put `https://banahaw.pages.dev` for now. You'll fix it in step 4
     if Cloudflare gives a different address.
4. Click **Apply**. The first build takes a few minutes. On start, the API brings the
   database schema up to date by itself. `JWT_SECRET` is generated by Render.
5. When the service shows **Live**, open `https://banahaw-api.onrender.com/health`
   (your address is at the top of the service page). It should show `{"status":"ok"}`.

The Starter plan (about US$7 a month) stays awake. The free plan sleeps after 15 idle
minutes, and the first booking after that waits about a minute, so it isn't suitable for the desk.

**You now have:** the API address, for example `https://banahaw-api.onrender.com`.

## 3. Create your spa and first admin

In Render, open `banahaw-api` > **Shell** and run (with your own email):

```bash
python -m app.cli create-tenant --name "Banahaw Heals Spa" --slug banahaw \
    --admin-email you@example.com --admin-name "Your name"
```

It asks for a password. The **spa code** staff type at sign-in is the `--slug`, here `banahaw`.

## 4. Cloudflare Pages: the web app

1. Sign up at dash.cloudflare.com, then **Workers & Pages > Create > Pages >
   Connect to Git** and pick `meroclemente12/sms`.
2. Build settings:
   - Project name: `banahaw` (this gives `banahaw.pages.dev`)
   - Production branch: `main`
   - Framework preset: **None**
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Root directory: `frontend`
   - Environment variable: `VITE_API_URL` = the API address from step 2, without a
     trailing slash
3. **Save and Deploy.** If `VITE_API_URL` is missing, the build stops with a message
   saying so instead of publishing a site that can't reach the API.
4. If the site address isn't `https://banahaw.pages.dev`, go back to Render >
   `banahaw-api` > **Environment** and set `CORS_ORIGINS` to the real address. To
   allow more than one address (for example a custom domain later), separate them with commas.

Open the site and sign in with spa code `banahaw` and the admin from step 3. Then use
**Setup** to add the branch, rooms, services, therapists, shifts and staff accounts.

## 5. Nightly backup

In GitHub, go to the repository's **Settings > Secrets and variables > Actions > New repository secret** and add:

- `BACKUP_DATABASE_URL`: the same Neon connection string as step 1.
- `BACKUP_PASSPHRASE`: a long random password. **Save a copy in your password
  manager.** Without it, no backup can be opened.

Then **Actions > Nightly backup > Run workflow** to try it now. A good run lists the
migration version and how many spas, bookings, clients and payments it restored. It
runs every night at 02:00 Philippine time and keeps each backup for 14 days. If a run
fails, GitHub emails you.

### Restoring a backup

1. In **Actions > Nightly backup**, open the run for the day you want and download the
   `banahaw-db-YYYY-MM-DD` artifact. Unzip it.
2. Decrypt it: `gpg --decrypt banahaw-YYYY-MM-DD.dump.gpg > banahaw.dump` (asks for the passphrase).
3. Make an empty database. A new Neon branch or project in Singapore is easiest. Then restore:

   ```bash
   pg_restore --no-owner --no-privileges --exit-on-error --dbname="NEW_DATABASE_URL" banahaw.dump
   ```

4. Give the API's role its permissions again (backups leave them out):

   ```sql
   DO $$ BEGIN IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'banahaw_app')
   THEN CREATE ROLE banahaw_app NOLOGIN; END IF; END $$;
   GRANT banahaw_app TO CURRENT_USER;
   GRANT USAGE ON SCHEMA public TO banahaw_app;
   GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO banahaw_app;
   ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO banahaw_app;
   GRANT EXECUTE ON FUNCTION tenant_id_for_slug(text) TO banahaw_app;
   ```

5. Point Render's `DATABASE_URL` (and the `BACKUP_DATABASE_URL` secret) at the new database.

## Releasing changes

Merging a PR into `main` deploys both parts. Render rebuilds the API and applies any
new migrations before it starts. Cloudflare rebuilds the web app.

## Production settings

| Name | Where | Value |
| --- | --- | --- |
| `ENVIRONMENT` | Render | `production` (set by `render.yaml`). The API then refuses to start with a missing or short `JWT_SECRET` |
| `DATABASE_URL` | Render | Neon connection string. Plain `postgresql://` works |
| `JWT_SECRET` | Render | Generated by Render. Changing it signs everyone out |
| `CORS_ORIGINS` | Render | The web app address(es), comma-separated |
| `SEED_DEMO` | Render | `false`. Never load the demo spa in production |
| `VITE_API_URL` | Cloudflare Pages | The Render API address |
